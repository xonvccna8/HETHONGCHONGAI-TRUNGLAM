# ORIGIN AI — Architecture

## Product boundary

ORIGIN AI is a document originality workspace, not a plagiarism verdict engine. It combines deterministic text comparison, optional semantic embeddings, verified source retrieval, citation analysis, writing-signal heuristics, and an AI-assisted revision workflow. AI-writing results are risk indicators only.

## Runtime topology

```text
Browser (Next.js / TipTap)
  ├─ REST routes + SSE progress
  ├─ Authentication/session boundary
  └─ Report and version comparison
          │
Next.js application service
  ├─ document parser (PDF/DOCX/TXT/MD)
  ├─ similarity pipeline (exact → fuzzy → semantic → rerank)
  ├─ SourceDiscoveryEngine → SearchProvider abstraction
  ├─ OpenAI Responses / embeddings adapters
  ├─ Citation Guard + Fact Preservation
  └─ PostgreSQL repositories
          │
BullMQ worker ─ Redis queue/progress/cache
          │
PostgreSQL + pgvector       S3-compatible object storage
```

## Core pipeline

1. Parse the document into sections, paragraphs, sentences and claims; preserve stable IDs and offsets.
2. Normalize text without destroying citations, numbers, names, dates or Vietnamese diacritics.
3. Retrieve candidates using exact shingles/rolling hashes and pgvector cosine search.
4. Score candidates using weighted exact, token/fuzzy and semantic signals, adjusted for length, quotations, citations and common knowledge.
5. Discover sources only through a configured `SearchProvider`; URLs are never generated by the language model.
6. Classify each sentence as `EXACT`, `HIGH_SIMILARITY`, `SEMANTIC_OVERLAP`, `COMMON_KNOWLEDGE`, `QUOTED`, `CITED`, `POSSIBLE_MISSING_CITATION`, or `ORIGINAL`.
7. Generate a structured review/rewrite proposal for suspicious passages only.
8. Compare claims and citations before accepting a rewrite. Any missing, added or changed fact becomes an explicit warning.
9. Persist a new immutable version, then re-embed and rescan only changed chunks.

## AI Council

When `AI_COUNCIL_ENABLED=true`, ORIGIN AI adds a bounded seven-agent review after the deterministic scan:

```text
Deterministic evidence pack
  ├─ Document Analyst
  ├─ Similarity Critic
  ├─ Source Auditor
  ├─ Citation Guardian
  ├─ Human Writing Coach
  └─ Adversarial Risk Reviewer
          ↓
Quality Reviewer → consensus + preserved disagreements + priorities
          ↓
Hard validators → UI / report
```

The specialists can run concurrently, but they cannot change a document or create a source. Each receives a read-only evidence pack, returns Structured Outputs, and is recorded with its model, latency, status and finding count. The Quality Reviewer does not use majority voting: deterministic evidence and confidence-weighted findings take precedence. Fact Preservation, Citation Guard and URL provenance remain non-generative boundaries after the council.

App-owned orchestration is the production default because this workflow needs a fixed, auditable graph. OpenAI Responses Multi-agent beta can later be enabled for open-ended research branches, but it is not used for irreversible decisions or citation provenance.

## Service boundaries

- `src/core`: pure, testable NLP and scoring logic.
- `src/ai`: OpenAI and source-provider adapters; all model IDs come from environment variables.
- `src/db`: schema and repositories. Business logic never imports a database driver directly.
- `src/workers`: long-running scan orchestration and progress publication.
- `app/api`: validation, authorization, rate/error boundaries and transport formatting.
- `components` and `features`: reusable UI and product workflows.

## Security and privacy

- All document input is treated as untrusted data, never instructions.
- Ownership checks occur server-side for every document and version request.
- Upload type, extension and size are validated; object access uses signed URLs in production.
- Rate limiting is enforced through Redis when configured.
- Raw documents can be marked ephemeral and removed after report generation.
- Provider calls receive only the minimum required passage. User documents are not used for training without separate, explicit consent.
- Secrets are server-only and model/provider names are configuration values.

## Graceful local mode

The deterministic exact, fuzzy, citation, fact, signal and scoring layers run without external keys. Semantic embeddings, web source discovery and high-quality AI rewrite are enabled only when their providers are configured. The interface labels unavailable external evidence clearly instead of inventing sources or scores.
